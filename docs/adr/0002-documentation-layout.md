# ADR-0002 Four-file documentation layout with single ownership

**Status:** Decided  
**Date:** 2026-06-14  
**Context:** Documentation reorganization prompted by accumulated duplication across CLAUDE.md, CONTEXT.md, docs/architecture.html, and docs/Claude_analysis.md

## Background

The project accumulated four files with technical documentation. By mid-2026 the same facts appeared in multiple files, one file was stale (pre-`BibliographicItem` rename, wrong class names, Spring Boot 4.0.1 version), and there was no rule governing which file owned which kind of information.

## Decision

Adopt a **four-file layout with explicit single ownership** per information type:

| Information type | Authoritative owner |
|---|---|
| Domain term definitions (concepts, modes, item types, validation) | `CONTEXT.md` |
| Service responsibilities, pipeline and sequence diagrams | `docs/architecture.html` |
| Algorithm details (steps, thresholds, INSUFFICIENT_DATA, special types, enrichment) | `docs/algorithm.md` |
| Commands, coding rules, test structure, configuration, release workflow | `CLAUDE.md` |
| Decision rationale (why X, rejected alternatives) | `docs/adr/` |

Each file may *reference* another file's material via a link, but must not restate it in full. CLAUDE.md keeps one-line orientation summaries of services, algorithm steps, and modes with links to the authoritative sources — sufficient for the agent to orient itself without requiring a separate read.

`docs/Claude_analysis.md` is deleted after its unique content (algorithm detail) is ported to `docs/algorithm.md`.

## Alternatives considered

### 1. Keep everything in CLAUDE.md

CLAUDE.md is auto-loaded into every agent session, making it the most visible file. The appeal is zero context-switching.

**Rejected** because: the file was already long, the architecture section was duplicating the service map, and adding full algorithm detail would push it past a useful reading length. CLAUDE.md's role is the agent operating manual, not a reference compendium.

### 2. Keep docs/Claude_analysis.md, just update it

The file was generated by a prior Claude session as a codebase analysis. It duplicated the service map from architecture.html and was stale on class names.

**Rejected** because: keeping it required maintaining two copies of service information. The useful content (algorithm deep-dive) was worth preserving, but in a proper reference document with verified class names and CONTEXT.md-aligned terminology — not in the analysis snapshot.

### 3. Merge everything into a single mega-doc

One large file with sections for each concern.

**Rejected** because: different audiences and update frequencies. CLAUDE.md is read every agent session; algorithm.md is read only when debugging a missed duplicate. Merging would burden every agent invocation with loading algorithm detail it doesn't need.

## What to watch for (conditions that would reopen this)

- CLAUDE.md's one-line orientation summaries become incorrect and the agent frequently needs to open architecture.html or algorithm.md just to orient itself — raise the inline detail level.
- algorithm.md falls out of sync with the code for more than one release — consider auto-generating it from tests or inline Javadoc instead.
