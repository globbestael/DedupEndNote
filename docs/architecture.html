DedupEndNote — Architecture

Spring Boot 4.1 · Java 21

A web application that deduplicates Bibliographic Items exported from reference managers. Runs on port 9777, deployed as a fat JAR.

1. Data pipeline

How a RIS file is transformed into a deduplicated result. In Two-file mode, BibliographicItemReader runs twice — once for the Old file, once for the New file — before the combined list enters the comparison step.

All five comparison steps must pass for a pair to be considered a Duplicate. The comparison short-circuits on the first mismatch, so cheap checks (year, page/DOI) run before expensive ones (Jaro-Winkler similarity).

See docs/algorithm.md for step details, threshold values, INSUFFICIENT_DATA logic, year-bucketing, special-type handling, and enrichment.

2. Service map

Services across three packages: edu.dedupendnote.services (pipeline), edu.dedupendnote.services.comparison, edu.dedupendnote.services.normalization. Spring beans unless noted.

Pipeline orchestration

DeduplicationService

Orchestrates the full pipeline. Accepts a Consumer<String> progressReporter for WebSocket progress. Runs in a virtual thread.

BibliographicItemReader

Parses RIS files into BibliographicItem objects; coordinates Normalization during read. Hosts addNormalized* instance helpers used by test fixtures.

BibliographicItemWriter

Writes deduplicated (Remove Mode) and marked (Mark Mode) RIS output; re-reads original input to preserve field order. Accepts a Consumer<String> progressReporter. In Remove Mode, owns all enrichment: calls EnrichmentService.enrich() (synthesise duplicate-set representation), EnrichmentService.enrichCochrane() (Cochrane page IDs), and EnrichmentService.enrichMap() per Kept Bibliographic Item during writing.

Run orchestration (controller-facing)

BoundedDedupRunner

Owns the concurrency permit (bounded Semaphore), the shared virtual-thread executor, the per-run timeout, and the cancel-by-session registry. runWithLimit() returns a RunOutcome (COMPLETED / BUSY / TIMED_OUT / CANCELLED / FAILED) and always releases the permit, even if a worker ignores interruption. The controller maps the outcome to HTTP status, output-file cleanup, and progress messages.

Enrichment (Remove Mode only) — called from BibliographicItemWriter

EnrichmentService

Three-phase enrichment, all called by BibliographicItemWriter in Remove Mode. enrich(): marks non-representative duplicates as not-kept, merges DOIs, fills missing year/pages, replaces Reply/ClinicalTrials.gov titles; also marks new-file duplicates of old-file items as not-kept (two-file mode). enrichCochrane(): uppercases Cochrane page IDs for all kept Cochrane items (both those with duplicates and singletons); must run after enrich(). enrichMap(): projects the enriched domain data and RIS-map-specific enrichments (T2 from J2, ClinicalTrials.gov URL normalisation, author cleanup) onto the raw RIS field map per Kept Bibliographic Item.

Comparison — wired via FieldComparators record

DefaultAuthorsComparisonService

Jaro-Winkler author matching. Thresholds injectable via AuthorThresholds record.

DefaultTitleComparisonService

JWS title matching. Thresholds injectable via TitleThresholds record.

DefaultJournalComparisonService

Journal matching with abbreviation/initialism heuristics. Hosts static compareIssns.

DefaultPagesComparisonService

Exact-equality pages-or-DOI step. Hosts static compareSameDois.

Normalization — called from BibliographicItemReader; not Spring beans

NormalizationService

Shared utilities: normalizeToBasicLatin, normalizeHyphensAndWhitespace, DOI/ISSN/year parsing.

AuthorsNormalizationService

Last-name + initials; transposed names; group-author detection.

TitlesNormalizationService

Retractions, reprints, subtitles, HTML tags, punctuation.

JournalsNormalizationService

Abbreviations, language variants, supplement strings.

PagesNormalizationService

SP/SE/C7 fields; Roman numerals; page-range merging; e-pages.

4. Modes

Remove Mode (default)

Duplicate Bibliographic Items are removed from output. The Kept Bibliographic Item is Enriched with data from its duplicates (DOI, year, pages, title).

Mark Mode

All Bibliographic Items are written to output. Duplicates are identified by their Label — the ID of the Kept Bibliographic Item written into the RIS LB field.
